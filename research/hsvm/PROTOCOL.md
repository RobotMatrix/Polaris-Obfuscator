# 实验协议预注册（M0-4）

本文件是 V1.3 §1.3/§10 的工程落地：**在任何实验跑之前**冻结参数网格、查询预算、
测试分布、模型大小上限、语义阈值、随机种子、停止规则与反作弊规则。
`protocol.json` 是机器可读版本，`tools/check_protocol.py` 强制其完整性并打印
`protocol_sha256`；每份报告必须引用该哈希。

改协议的唯一方式：写 `DECISIONS.md`（日期、字段、旧值、新值、理由、受影响的门禁），
然后重算哈希。**不允许事后修改后继续用旧哈希的报告。**

## 1. 主假设（§1.3）

> 存在参数点 (w, c, ψ 构造, 编码族)，使得在 A2 攻击者、至多 2^40 次有效查询、
> 且 R_plain ≤ 3 的条件下，攻击者恢复紧凑语义模型的成功率低于 10%。

- `query_budget = 2^40`：预注册预算，不是由 w 推导的复杂度下界。
- 成功率按独立密钥实例统计（`instances = 16`，`confidence = 0.95`）。
- 预算未用尽 ⇒ 必须 `censored=true`，措辞只能是"在已用预算内未成功"。

## 2. 阶段 1 门禁（§10 阶段 1）

| 项 | 值 | 说明 |
|---|---|---|
| 查询预算 | 2^32 | 插值攻击预注册预算 |
| 插值成功率阈值 | < 1% | 未完成预算只能报右删失 |
| Γ 5% 分位 | ≥ 0.5 | 按指令类型报分布/中位数/CI |
| 每实例状态样本 | 4096 | D_reach 采样量 |
| 每实例核方向 | 256 | δ = B_K·r，r 均匀 |
| 非仿射检验 | dim ≤ 16 穷举，否则抽样 | 抽样结果不得写成证明 |
| R_plain | ≤ 3 | 30 次重复取中位数，报 p5/p95 |
| R_commercial | ≤ 1.5 | **基线未选型**，见 DECISIONS/开放问题 |

## 3. 参数网格与冻结点

网格见 `protocol.json` 的 `params_grid`；`chosen_point` 在当前阶段为 `null`，
必须在 M2-10 由模型层实验选定后写入，并重算协议哈希。写入后，阶段 1 的所有
报告只能用该点（其他点只能作为网格扫描记录，不能作为门禁证据）。

网格合法性由 C++ 的 `validate()` 定义（`include/hsvm/params.h`）：
`m<n`、`w<=n`、`c<=n`、`c*r_bar<=n`、table 档 `w<=16 且 rounds==0`、
spn 档 `w%8==0 且 1<=rounds<=16`、`seed!=0`。
Python 检查器对网格做同样的逐点校验；`chosen_point` 非空时还会调用
`hsvm_params` 交叉验证。

## 4. 攻击者模型与查询计数

- **A2（定点进程控制）**：可读写 VM 状态缓冲、bytecode、分发表、检查点；
  可替换调用目标、Hook 单步边界；**不可**改内核代码映像（那是 A3）。
- 一次有效查询 = 攻击者选定输入后获得的**一次**单步转移及其约定观测；
  长度 L 的 trace 计 L 次转移查询。
- 不同攻击等级（A1/A2/A3）的结果不得合并成一个数字。

## 6. 停止规则（§10.1）

1. `stage1_no_feasible_point_under_r_plain_3`：在 R_plain ≤ 3 下遍历已登记网格，
   找不到同时满足 Γ p5 ≥ 0.5 与非仿射检验的 (w,c) ⇒ 终止 C1/C2 路线。
2. `stage2_whitebox_recovers_psi_or_compact_model`：BGE/DCA 在 2^32 内恢复 ψ、
   规范状态或达 §7.3 阈值 ⇒ 当前编码族判死，换族须从阶段 1 重来。
3. `core_hypothesis_success_rate_at_least_0_10`：主假设被直接否证，且调参无法回到
   R_plain ≤ 3 ⇒ 终止。

阶段 4B 的 P1 负收益**不**触发上述任何一条（§10.1 末段）。

## 7. 反作弊规则（§7.3）

1. 报告中所有数字由脚本生成；`tools/report.py` 拒绝无 `raw_log` 的成功率声明。
2. 每份报告绑定：`git_commit`、`binary_sha256`（或模型/语料哈希）、`params_hash`、
   `protocol_sha256`、`seeds`。
3. 预算未跑完 ⇒ `censored=true`；不得写成"成功率低于阈值"。
4. 参数变更必须记 `DECISIONS.md`，禁止事后改协议。
5. 负结果与失败脚本原样归档，不得删除重跑"洗"结果。
6. 每个攻击脚本必须带阳性对照（在无防护基线上成功），否则其失败不构成证据。
