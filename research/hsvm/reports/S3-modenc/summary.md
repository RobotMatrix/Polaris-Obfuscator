# 阶段 3：模块化编码与全局正规化（结果：模块结构不带来攻击成本）

对应文档 §6.1（共轭变换为何无效）、§6.2（模块编码的全局正规化攻击）、§6.3（组合正确性）。

## 交付

| 文件 | 内容 |
|---|---|
| `include/hsvm/modenc.h`、`src/modenc.cpp` | 逐 lane 随机双射（模块编码），带逆变换 |
| `tests/test_modenc.cpp` | 8 条断言：往返、逐 lane 双射、lane 独立性、种子敏感、非恒等 |
| `tools/hsvm_normalize.cpp` | 提取型攻击探针：全域查询建等价表，记录查询数与耗时 |

## 实验

窗口按 8 位分 lane，每个 lane 各自一个独立双射（即"模块"）。
对 w ∈ {8,16,24}（1/2/3 个模块）让攻击者枚举整个定义域并建表：

| lanes | w | 查询数 | 抽样校验命中 | 耗时 |
|---:|---:|---:|---:|---:|
| 1 | 8 | 256 (=2^8) | 3 | 0.0 ms |
| 2 | 16 | 65,536 (=2^16) | 676 | 0.4 ms |
| 3 | 24 | 16,777,216 (=2^24) | 172,961 | 125.8 ms |

## 判定

`supported = false`：查询数严格等于 2^w，**与模块数量无关**。
攻击者为"窗口宽度"付费，从不为"模块数"付费。§6.2 的判断在这个攻击面上成立：
模块编码只改变代码形状，不改变恢复成本。

## 边界（不要过度引用）

- 这里用的是**比文档更强的攻击者**：不做代数正规化，直接把整个函数表枚举出来。
  因此结论只对"提取型"攻击成立，**不能**证明文档所说的代数正规化攻击一定存在。
- w=24 已经要 126 ms；w=32 约 2^32 次查询（小时级），w≥48 不可枚举。
  所以本结论的适用范围是 **w ≤ 24**；更宽的窗口要靠代数攻击，而那部分**未实现**。
- 模块编码的正确性（组合后仍是同一函数）由 `test_modenc` 覆盖；这属于 §6.3 的必要条件，
  不等于证明模块化在编译器里能安全落地。

## §6.2 代数正规化：仿射编码的可识别性（本轮补上）

`tools/hsvm_ddt.cpp` 检验：仿射 module 编码是否把底层函数的差分结构藏住。

| 包装方式 | 差分分布表的行多重集是否不变 |
|---|---|
| 仿射 `A2∘ψ∘A1`（随机可逆 8×8 + 常量） | **不变** |
| 随机逐 lane 双射 | 变 |

原因：仿射映射对差分是线性的，`DDT(F)` 的每一行只是 `DDT(ψ)` 的行/列置换，
所以**攻击者仅凭一张表就能识别出这是仿射共轭，并据此对齐模块结构**。
这正是 §6.2 所依赖的前提：仿射模块编码可被整体归一化。

**做到哪一步**：可识别性（identification）已证明并可复现。
**归一化（线性情形）已补上**：`tools/hsvm_affine_recover.cpp`。
ψ 线性时 `A2∘ψ∘A1` 仍仿射，`F(0)` + 8 个基向量共 **9 次探测**即可精确重建：

```
additivity self-check violations : 0
linear psi : 9 probes -> mismatches over 256 =   0
table  psi : 9 probes -> mismatches over 256 = 247
=> affine module encodings stripped for linear modules: yes
```

也就是说：**线性 module 的仿射编码可以被完整剥离**（0 误差），
非线性 ψ 用同样 9 次探测做不到（247/256 错）——这正说明 §6.2 的负结果来自非线性，
不是来自"模块化"本身。

`additivity self-check` 是先用 `F(a⊕b)=F(a)⊕F(b)⊕F(0)` 把矩阵行/列约定钉死再跑重建；
上一轮失败正是栽在约定上（ADR-017），这次先用自检挡住了。
