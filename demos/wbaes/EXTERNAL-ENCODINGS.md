# 外部编码（离线路线的上限）：设计与判据

## 背景

dl3 暴露的问题不是"轮数可见"，而是**每张表里直接含着 S(x⊕k)**：取一行反 S 盒即得密钥，
所以异构轮只把脚本从 5 s 拖到 27.7 s，强度没有提高。dl4 补的是内部编码（把表项放回编码域），
它把成本恢复到 dl2 的水平——仍然是秒级。

离线上真正能改变成本量级的只有**外部编码**：让主密钥不出现在任何一张表里，
攻击者必须解一个规模化的非线性方程组（BGE / Karfreit 类），而不是"读一行表"。

## 设计

```
明文 m ──[ 输入外部编码 A ]──> 编码域 ──[ 9 轮异构表 + XOR 网络 ]──> 编码域密文 ──[ 输出外部编码 B ]──> 密文 c
```

1. **输入外部编码 A**：16 个独立随机双射（每字节一个），由调用方持有；表区按 A 域建。
2. **输出外部编码 B**：末轮输出再套一层 32 位混合双射（4×8 位表 + XOR），密文在 B 域里产生。
3. **内部编码**：轮边界随机双射 + 每张表输入/输出编码，XOR 在编码域做（与 dl4 同构）。
4. **解密镜像**：A⁻¹ / B⁻¹ 分别在首尾，内部编码方向相反。
5. **约束**：密钥只在生成端出现，产物里不得有任何表项等于 `MC·S(x⊕k)` 或 `S(x⊕k)`；
   `HY_MASK_SEED` 依旧与密钥无关（四字 volatile 分片）。

## 判据（缺一条就不算完成）

| 编号 | 判据 | 方式 |
|---|---|---|
| E1 | 函数不变 | 固定向量 `6bc1bee2…` 在编码域路径上解码后仍得 `e5a25174…`（或换钥后的对应值） |
| E2 | 表项不含密钥 | 脚本扫描全部表区，任何 256 项窗口都不等于 `S(x⊕k)` 或 `MC·S(x⊕k)` 的整表（对 16 个 k 全试） |
| E3 | 提取器失败 | `extract_key.py` 在产物上必须失败，并给出清晰原因（不是超时） |
| E4 | BGE 攻击评估 | **必须写一个 BGE 风格脚本尝试还原**，报告：成功/失败、代数规模、耗时。失败要说明卡在哪一步 |
| E5 | 双算不退化 | `-DWBAES_DFA_SELFTEST` 下仍输出垃圾并 `vector-match FAIL` |
| E6 | 自检 | 生成端 `return 9` 分支与 demo 回环自检均通过 |
| E7 | 一致性 | 产物仍能被"自己的明文/密文对"复核（用 openssl 独立重算） |

## 诚实的预期

- E3 大概率能达成（脚本只认 `S(x⊕k)` 形状）；**这不等于安全**。
- E4 才是真正的度量：Chow 类实现历史上被 BGE 在约 2^30 级工作量下破过，
  外部编码能挡住"脚本级"攻击，挡不住"研究者级"攻击。离线单二进制的天花板就在这里。
- 若 E4 显示 BGE 几分钟就能还原，那就该如实写"无效"，而不是继续加层。

## 顺序

1. 等 dl4（内部编码）落地并复核通过——否则外部编码建在漏表的底座上，评估没有意义；
2. 实现 A/B 与内部编码的组合，先只做加密方向，跑通 E1/E2/E6/E7；
3. 补解密镜像，跑 E5；
4. 写 BGE 评估脚本，跑 E3/E4，按实测结果决定是否值得导出 `dl5`。
