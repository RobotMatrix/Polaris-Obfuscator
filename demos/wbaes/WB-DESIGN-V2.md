# 白盒方案 v2：设计、判据与已知上限

## 一、威胁模型（先说清对手是什么）

对手拿到**产物本身**（二进制 + 运行期内存 dump），离线作业，目标是以下二者之一：
- T1 还原主密钥（可离线解密历史流量）；
- T2 不还原密钥也能伪造/解密任意密文（表级替身攻击、故障注入）。

明确**不在**范围内：服务端下发、在线校验、设备证书——本项目只做离线产物。

## 二、现状盘点（每条都有实测依据）

| 组件 | 现状 | 实测依据 |
|---|---|---|
| 表编码 | dl4：每族每 lane 随机双射 + 成对解码表，XOR 在解码之后 | 提取器 27.5 s `no candidate key` |
| 轮实现 | 异构：F0/F1/F2/F3 按轮调度，含 64 B 调度块 | 四种族强制 + 混合密文一致 |
| 静态表 | 数据层 XOR 掩码，种子 4 字 volatile 分片（与密钥无关） | dl2/dl3 种子均被还原，代价 +1.2 s |
| 故障防护 | DFA 双算（两份独立缓冲，不一致输出垃圾 + `g_key_tampered`） | `-DWBAES_DFA_SELFTEST` 输出三份不同垃圾 |
| 完整性 | 全表 FNV 封印 + 每 4 KiB 抽样 | 改一字节 → 密文错、`vector-match FAIL` |
| 控制流 | HSV VM 算每轮表偏移（ISA v2 `Tld`，在加解密热路径上） | `nm` 有 `_hsvm_entry`/`_hsvm_bytecode`、`_hsvm_entry` 里间接跳转 0；改调度块一个字节 → 密文变、自检失败（README §5.26） |

历史曲线（同一脚本）：**dl 4.9 s → dl2 5.0 s → dl3 27.7 s → dl4 失败（27.5 s 未出钥）**。
注意 dl3 的 27.7 s 是"脚本要支持三种形状"，不是强度；dl4 才是第一次让提取器真正失败。

## 三、设计原则（从失败里总结的，不是教科书抄的）

1. **秘密不落在产物里**。任何"解掩/解码所需的常量"只要在产物内就可读——
   dl2 的种子被 4 个字还原、dl 的种子等于密钥的 FNV，都是这条的代价。
2. **编码必须随机，不能仿射**。仿射层可剥离（§6.2：线性 ψ 9 点探测 0/256 误差；
   dl4 的一次实测也显示 GF(2) 线性 lane 掩码 0.11 s 即被解出）。
3. **每条"更强"的主张必须配一个攻击脚本**，脚本失败才算数（E3/E4 判据）。
4. **异构 > 加深**。9 轮同构让识别器一次成型；异构让攻击者为每种形状单独写代码。
5. **故障与完整性分开处理**：DFA 双算防"一次注入取差分"，封印防"改表"，两者不互相替代。

## 四、v2 架构（分层）

```
  明文 m
    │  ① 外部输入编码 A（16 个随机双射，调用方持有；离线时编进调用侧）
    ▼
  编码域状态 ──② VM(HSV 字节码) 计算本轮表偏移与调度 ──┐
    │                                                 │
    │  ③ 9 轮异构表网络（F0/F1/F2/F3 按调度；每 lane 随机双射，
    │     成对解码表；XOR 在解码后）
    ▼                                                 │
  编码域密文 ──④ 输出外部编码 B（32 位混合双射）◄───────┘
    │
    ▼  密文 c（B 域）
  ⑤ DFA 双算：整条链跑两遍，独立缓冲，不一致 → 垃圾输出 + 篡改标记
  ⑥ 完整性：全表 FNV 封印 + 采样；掩码在解掩后按明文抽样复核
```

关键点：**主密钥不出现在任何一张表里**（这是 ①④ 的作用）。表里只有编码域里的函数值，
攻击者要还原密钥必须解一个跨轮的代数方程组（BGE 类），而脚本级读取直接失效。

## 五、VM 的位置与边界（硬要求）

- 位置：②——每轮的表偏移/调度计算，`Tld` 读 4 KiB 内存中的调度块，结果 `St` 回内存；
- 边界：不把 69 MB 表搬进 VM 内存（不可能），VM 只做"算偏移 + 调度"，是热路径但非数据面；
- 判据：改坏调度块一个字节必须让自检失败（证明 VM 输出真被使用），
  且产物里没有解释器分发循环（lowering 后是原生代码）。
- 现状（2026-11-17）：已落地并实测。`hy_mc_round` 的每个表地址来自 VM 返回的偏移，
  一个块 288 次 `hsvm_entry`（16 偏移 × 9 轮 × 2 方向），单次 40.5 ns，
  每块加密 4.11 → 10.56 µs、解密 4.83 → 11.33 µs。数据面（69 MB 表）仍在宿主内存，
  这是 ISA 的边界，不是实现偷懒：`Tld` 只能读，写出只有 `r0`。

## 八、上限（写在设计里，防止自我安慰）

离线单二进制 + 无服务端 ⇒ 攻击者最终总能拿到"完整的解密算法"；
差别只在**成本**：脚本 5 s、研究者数天、还是需要专门论文级的代数攻击。
v2 的目标是把成本从"脚本级"推到"研究者级"，并把这个跨度量出来——
而不是宣称"解不开"。任何"解不开"的表述都不允许出现在文档里。

## 九、行业现状调研（用于校准我们的目标）

**学术结论（有出处）**
- 截至 2023-01，公开文献里**没有**未被攻破的"标准对称算法"白盒实现；只有专为白盒设计的
  专用分组密码（追求不可压缩性）才有未破构造（Wikipedia, White-box cryptography）。
- BGE（Billet–Gilbert–Ech-Chatbi）及其改进把 Chow 类 AES 的工作量降到 **2^22** 量级
  （"Two Attacks on a White-Box AES", KU Leuven）。
- **DCA（Differential Computation Analysis）** 是关键一击：不读表、不逆向，只用动态插桩记录的
  内存访问轨迹做相关分析，就提取出**所有公开可得**的白盒程序的密钥（Bos/Hubain/Michiels/Teuwen,
  CHES 2016, ePrint 2015/753；工具链开源 SideChannelMarvels）。
- 商业产品同样被实战攻破（Phrack 68/8 "Practical cracking of white-box implementations"）。

**商业实现的共同思路（不是公开算法，是从攻破报告里反推的）**
```
外部编码   输入/输出各套一层编码，密钥不落表 —— 与本文 §四 的 ①④ 同构
宽表 + 掩码 4→8 位拆表、随机双射、每构建重新随机化
DFA 对抗   内部冗余校验、双算、随机化执行顺序
最后防线   越来越多的厂商把真正的密钥放进 TEE / 安全元件（Widevine 的 CDM、PlayReady 的 SL3000），
           白盒只保护"会话密钥/内容密钥的短生命周期"
```
  也就是说：**行业并没有解决纯软件白盒的密钥保护**，而是把密钥生命周期缩短到 TEE 里。

**对我们的直接修正**
1. 我们的攻击面清单必须加 **DCA**：`E4c` 用插桩记录表访问地址，做 CPA/相关性分析，
   看能否在不知道表结构的情况下恢复轮密钥。这条比 BGE 更容易实现，且历史上更致命。
2. 我们的 `dl4` 之所以让脚本失败，是因为表项做了随机编码；但**访问地址**仍然泄漏索引，
   DCA 需要的正是这个。必须实测，不能假设。
3. 结论层面的定位确认：离线纯软件方案的天花板是"脚本失效、研究者级攻防仍可行"，
   与行业现状一致；文档里禁止出现"安全/不可破"的措辞。

## 十、两条提议的评估：虚拟保护 vs 多算法并用

### 10.1 虚拟保护（VM）——控制流层，值得做，但不保护密钥

已有结论（`VM-REQUIREMENT.md`）：VM 内存 4 KiB、16 寄存器，69 MB 表进不去，
所以 VM 只能承载"每轮表偏移/调度计算"，属于热路径但非数据面。

它的真实价值与真实边界：
- 有价值：轮边界变成字节码 → lowering 后是原生代码，没有统一的分发循环可识别；
  攻击者要理解数据流必须逐段还原，成本上升。
- 边界：**它不改变"表被读到就能用"这件事**。VM 化之后，攻击者依然可以 dump 表、跑提取器。
  所以 VM 是"提高静态理解成本"，不是"提高密钥保护强度"。任何把 VM 当密钥防护的说法都不成立。

### 10.2 多算法并用——分三种情况，只有一种是真提升

| 方案 | 攻击者拿到同一份产物时 | 结论 |
|---|---|---|
| 复合加密（AES 后再套 Serpent/ChaCha，两把独立钥） | 两把钥都在产物里，提取成本 ×2 | 只是常数倍，不改变"能否提取" |
| 阈值拆分（主钥 = K1 ⊕ K2，两份分别编进两套表） | 同一产物里两份都在，等价于一把钥 + 更多表 | 无提升 |
| 拆分 + 秘密不在产物内（口令 / 设备秘密 / 服务端） | 缺一份就无法解密 | **真实提升**，但已偏离"纯离线单产物" |

关键区分是**攻击目标**而非算法数量：
- 若攻击者的目标是"用你的程序解出内容"（DRM 场景），多算法完全无效——他不需要钥，只需要调用你；
- 若目标是"离线还原密钥、解历史流量"，多算法的唯一收益是把提取成本乘以密钥份数；
- 只有当其中一份密钥**不在产物里**时，才会从"脚本级"跳到"需要另一个秘密"。

### 10.3 落地建议（按性价比排序）

1. **VM（进行中）**：控制流异构，成本低，收益真实但仅在"理解成本"维度。
2. **复合加密作为常数倍**：若要抗"提取单钥即可解历史数据"，可做 AES + 第二套算法、
   两把独立钥编进两套异构表；接受表体积翻倍（约 138 MB）与提取成本 ×2 的现实。
3. **真正的类跃迁**（若产品允许）：主钥 = 编进产物的 K1 ⊕ KDF(口令/设备秘密)，
   产物内只有 K1；缺 K2 时产物只能解出噪声。这条不依赖服务器，只依赖"用户/设备持有的秘密"。
4. 若既不允许服务器也不允许任何外部秘密，则上限就是 §八 写的"研究者级"，
   多算法只提供 ×N 的常数项——不要把它包装成更强的安全等级。

### 10.4 与现有攻击闸门的对应

- VM 的效果由 `V2`（改坏调度块必须自检失败）+ `V4`（性能不得退化）度量；
- 多算法的效果由 `E3`（脚本提取成本）×N 与 `E4c`（DCA 地址泄漏，与算法数量无关）度量；
- 注意：**DCA 不因多算法变难**——它攻击的是"索引与密钥的相关性"，两套实现就有两条泄漏面。
  所以 10.3 的第 2 条若采用，`E4c` 必须对两套各跑一遍。

## 十一、E4b / E4c 实测：两条都成功（2026-11-17）

脚本在 `demos/wbaes/attacks/`（`dca_attack.py`、`bge_attack.py`、`trace_harness/`，
README 有逐条命令）。对手是 `wbaes_dl4_clean`（key `755e…`，密文 `abe296ee…`）。
下表每条数字都来自本机实跑。

| 攻击 | 需要什么 | 轨迹 | 结果 | 耗时 |
|---|---|---|---|---|
| E4c-A 经典单字节 DCA | 插桩，仅地址 | 64 | 失败（噪声，原因见下） | 0.5 s |
| E4c-B 边界表下标 + 4 字节 MITM | 插桩，仅地址 | 5（8 条余量） | **全 16 字节主密钥** | 0.19 s |
| E4b 解码表 XOR 分解 | 表字节（解掩） | — | **全 16 字节主密钥** | 0.01 s（解掩后） |

### E4c：地址仍然漏，但漏点不是 lane 表

1. 经典 1 字节 CPA（假设 `S(pt^k)`，与第 0 轮 lane 表地址相关）**失败且原因明确**：
   16/16 个槽位的下标在 64/64 条轨迹上逐位等于 `P0(pt)`（公开双射），与密钥无关；
   max|r| = 0.497，而"256 个假设取最大"的蒙特卡洛零分布是 0.414，真字节排名 7–248。
   把 `rk0` 从索引挪进表值这一步是有效的。
2. 真正的漏点是 `F1/F2/F3` 那张 256 项**边界置换表**：它的下标是 `MC(row,:)·S(pt^rk0)`，
   即 AddRoundKey **之前**的轮输出。`hy_scatter8` 是仿射模 256，索引可整字节反解，
   于是一条轨迹 = 一个 8 位方程、4 个密钥字节，MITM 后每列唯一：

```
tag F1 (kind 20): candidates per column [1,1,1,1] -> 16/16 key bytes  [0.19s]
755e563b1dffd249ef552c1bb778de29   (8 address traces, no table bytes)
reproduces the shipped ciphertext: YES
```

   轨迹数曲线（每列候选数）：2 → ~66k；3 → ~250；4 → 2–4；5 → 1。
   第 1 轮以后同一张表的下标是上一轮边界双射的输出（未知双射作用在含密钥的值上），
   地址无法与任何密钥假设挂钩，所以链条只在**入口轮**断——而入口轮正是 `rk0`（=主密钥）。

### E4b：64K 解码表是 XOR 可分解的，lane 双射没有起到作用

`pair(row,p)[a,b] = D0[a] ^ D1[b]` 是秩 1 张量：读一行加一列即可拟合出两个 256 字节数组。
全量校验（32 张表 × 65536 项）：

```
2097152 of 2097152 entries reproduced exactly by two 256-byte arrays
recovered D is a permutation in 32/32 tables
```

于是第 0 轮 lane 表 + `D` 直接给出 `MC[row][k]·S(pt^key)` 的 256 个值，候选密钥字节唯一
（16/16，四个 MC 行互相一致），AES-128 密文复现。**跨轮代数一步都没用上**：§四 里
"攻击者必须解一个跨轮的代数方程组"这个前提在第一步就不成立。

### 两条修正（结构性推导，不是测量）

1. §四 的"表里只有编码域的函数值，必须解跨轮方程"不成立：只要重组合是 XOR、每条 lane 一个
   逐元素双射，解码表必然是 `D0[a]^D1[b]`，逐 lane 的逆一定可分；换更大的表、加轮、
   换调度都不改变这一点。要去掉它只能放弃逐 lane 编码，走宽表（32 位输出）上的非线性编码
   （§五 的 Chow 式融合方向），代价是表规模，且那条路上 BGE 类攻击直接适用。
2. `E4c` 的判据要写细：不是"地址是否泄漏索引"，而是"**是否存在下标恰为密钥白化后的
   明文域值的表**"。第 0 轮边界置换表就是；把它换成 64K 表只能把 8 位方程换成 16 位方程，
   仍是泄漏面。

未测：`dl4_max`、`dl2/dl3`、解密路径的入口轮、VM 产物（`wbaes_vm_*`）。不要从本节外推。

## 十二、dl5：跨 lane 非线性重编码，两条攻击都失败（2026-11-18）

§十一 的两条修正被落地成 dl5，并对同一批脚本复测。结论先说：**这两条脚本在 dl5 上都失败，
原因在脚本自己的输出里；但"失败"只针对这两条脚本，不等于产物不可攻破**（见本节末尾的上限）。

| 攻击 | dl4 | dl5 | dl5 卡在哪 |
|---|---|---|---|
| E4b BGE（静态读表） | 全 16 字节密钥，0.01 s | `incomplete (0/16 bytes)` | 第一步：64K 成对表加了随机输出双射 `Z`，`Q[a][b] = Z(D0[a]^D1[b])` 不再是秩 1 张量；122400 个非轴向项只复现 974 个（0.80%，随机期望 0.39%），拿不到 `D`，第三步无候选 |
| E4c DCA（地址轨迹） | 全 16 字节密钥，8 条轨迹 0.19 s | `0/16 bytes`，6 个 (tag, half) 组合全 0 候选 | 下标从 1 字节变 2 字节：`(Zl(x), Zr(y))`，`x,y` 是两条成对解码输出的和；`Zl/Zr` 只在表值里，密钥假设预测不出下标 |

### 12.1 为什么这样改，而不是"加大表/加轮"

§十一 的推导是结构性的：XOR 组合 + 每 lane 一个逐元素双射 ⇒ 解码表必然 `D0[a]^D1[b]`，
换更大表或更多轮都不改变可分性。所以 dl5 只做两件事：

1. 在 64K 成对表的**输出**上加随机双射 `Z`（表值 = `Z(D0[a]^D1[b])`），
2. 把轮边界从 256 项换成 64K 两字节表，值 = `P[Zl⁻¹(u) ^ Zr⁻¹(v) ^ rk]`。

`Zl⁻¹`、`Zr⁻¹` 不作为数组存在，只作为这张 64K 表的值被"用掉"；这就是 §十一 那句
"逆必须依赖一个不是表项本身的值" 的最小实现。

### 12.2 32 位跨 lane 重编码：能放哪，不能放哪（结构结论）

要求是"四条 lane 查表 XOR 成一个 32 位字，再过一个可逆非线性 32 位重编码"。实测得出的约束是：

- 32 位非线性**不能**插在"成对解码 → 边界"之间：边界要算 `x_r ⊕ y_r`，而 4 字节混过之后
  单行信息已经不可恢复，2 字节表无法还原；
- 也**不能**只放在状态路径上指望下一轮"逐字节吸收逆"：`R⁻¹` 的三个 `MDS⁻¹` 都混四字节，
  下一轮的 lane 表按单字节取下标，吸收不了。

所以 dl5 把重编码放在**轮输出**：一列的四个字节过 `R`（三轮：异或每轮常量 → 逐字节随机双射
→ 固定 4×4 MDS `(1,4,3,7)`，逆 `(11,11,9,8)`，生成端校验互逆且所有方子式非零），
下一轮开头由 `hy_rec_undo()` 用**存的逆向 S 表 + 代码里的 `MDS⁻¹`** 还原。它的逆因此不是
四张独立 256 项映射，也从不落盘。

诚实地说清它的价值边界：这是**状态编码**，不是代数屏障。解掩 `__hytab` 后读到 12 张逆向 S 表，
配合公开的 MDS 就能求逆；它买到的是"轮边界内存/寄存器里没有单字节明文域状态"、
"单字节故障扩散成四字节"（V5 的垃圾输出仍是垃圾），以及成本。**它不提高"能否提取密钥"的上界。**

### 12.4 剩余攻击面（本次**未**实现、未测，不许当成已挡住）

   属于 Biryukov–Shamir 类问题；本仓库没有实现，**不声明它不可解**。

## 十三、VM 层的提升空间（基于当前实测）

### 13.1 (a) `Z` 不是密钥屏障：它是输出侧重标号

`Q[a][b] = Z(D0[a]^D1[b])` 的每一行、每一列都是 256 个输出值上的置换（32/32 张表实测），
所以 `lam_a = f_a ∘ f_0^-1 = Z(Z^-1(y) ^ (D0[a]^D0[0]))` 可直接算出，`LAM = {lam_a}` 是 256 个
对合组成的群、在值集上正则作用、同构于 `(Z2)^8`；列方向给出 `D1` 一侧且落在同一个群里。于是

```
2097152/2097152 entries over 32 tables rebuilt as Z(da[a]^db[b]), Z a bijection in 32/32
remaining freedom: |GL(8,2)| * 2^8 = 1369104324918194995200 = 2^70.2
```

即：**表项全部被解释，`Z`/`D` 的字节标号留下 2^70.2 的自由度**。§12.4 第 1 条说的隐藏位移
确实不可唯一确定——任何"恢复了 Z"的说法都是错的——但这**不影响取密钥**：

- round-0 lane 表第 `r` 字节 = `E[r][k][ m[r][k]·S(P0^-1(enc) ^ rk0) ]`，而 `D[r][k] = E^-1`
  就是上面恢复出来的标号，所以 `val = D[byte]` 等于 `m·S(·)` 复合一个**未知线性映射** `B`；
- dl4 的判据（`val` 等于 `m·S(pt^g)` 差常数）必然失效：把 gauge 强制成恒等，实测 **16 个字节 0 候选**；
- 它的 gauge 不变形式成立：存在 GF(2) 线性 `A` 使 `val = A(m·S(pt^g)) ^ const`。真钥取 `A = B`。
  错误假设要求 AES S 盒与自身某个输入平移**线性等价**，实测 64 个 (列,lane,行) 位置 × 256 个假设
  **全部恰好一个候选**。

```
candidates over all 64 (col,lane,row) positions: min 1 median 1 max 1
the four MC rows agree on the candidate set for 16/16 (column, lane) pairs
recovered key: 46f6abe52990556a6713141f65fed9a5
reproduces the shipped ciphertext: YES
work factor: 16384 affine-consistency tests (64 byte positions x 256 guesses), 32 group recoveries
no search over Z, no search over D0/D1, no traces; 21.99s total (5.37s algebra)
```

要点：`rk0` 是**主密钥**，而它从**输入侧**进表；`Z` 只重标号**输出侧**。
只要"两条 lane 的逐字节双射做 XOR"这个形状还在，`Q` 的行/列置换就把 `D` 交到线性 gauge 为止，
而"是不是这一轮的 S 盒"这个判别式对线性重标号天然不敏感。**加 `Z`、加大表、加轮都不改变这条。**

### 13.2 (b) 边界下标是未知双射，但它是**固定**双射

`u_t = Zl(x_t)`、`v_t = Zr(y_t)`，`Zl/Zr` 未知但固定，所以 `u_t = u_t' ⟹ x_t = x_t'`。
4096 条真实轨迹让 `u` 的 256 个值各出现约 16 次（~32k 个碰撞对，脚本取 2000 个），
每个假设 `(k0,k1)` 在对上的签名为 `m0·(S(pt0_a^k0)^S(pt0_b^k0))`；真钥就是两个签名相等的那一对，
256 对 256 哈希求交把每半 2^32 压成 2×256 次签名计算。

```
col 0 half 0:  2000 collision pairs -> 1 candidate 2-byte key(s)  ['0x460x90']   ... 8/8 halves 1 candidate
traces used: 4096; candidate 2-byte sets per half: [1,1,1,1,1,1,1,1]
MITM cost: 512 signature evaluations per half, 8 halves, 1.03s; 5.11s end to end
```

轨迹数曲线（同一批真实轨迹）：32 条 → 4/8 独一（有的半 0 候选）；**64 条 → 8/8 独一**；
128/256/512/1024/4096 条同样 8/8。§12.4 第 2 条估计的"约 2^12 条轨迹"偏保守约 6 倍。
本攻击**不读表字节**，只看地址与明文。

### 13.3 (c) 重编码可以精确反演，但反演之后卡在 `Z`

```
stored inverse S-tables that are exactly the inverse of the stored forward S-table: 864/864
R^-1(R(x)) == x on 1152/1152 random 32-bit words over all 72 instances
single-byte fault at the round output -> changed bytes out: {3: 3, 4: 285}
round 0 output, recoding inverted: each byte is a bijection of the real AES state byte (conflicts 0 / 512 pt)
pair table fit D0[a]^D1[b]: 16338/2080800 = 0.0079 off-axis   -> peel yields 0/16
```

即 `R^-1` 完全公开（12 张逆向 S 表就是正向表的逆，配合公开 `MDS^-1`），反演后剩下的形状
与 dl4 完全一致（逐字节双射 + 未知双射 `Z` 包住的成对和），于是 dl4 的剥离在此仍然 0/16。
重编码买到的是"轮边界寄存器里没有明文域单字节状态"和"1 字节故障扩散到 4 字节"（288 样本中 285 个），
**不是密钥提取上界**——这两句 §12.2 已经写明，本次把它测出来了（反演 0.19 s、0 个密钥比特）。

### 13.4 (d) 同钥异码：一份被打穿就等于全部

用 `gen_hybrid.cpp` 在临时目录生成两份（同钥、编码独立随机、`/dev/urandom`）：

```
A/B 表不同 (seal 0xadd2dade / 0x9b13b496), P0 不同, 各自 5.4s 取回同一个密钥 46f6abe5…
Q_A ^ Q_B 拟合 D0[a]^D1[b]: 493/130560 = 0.0038 (随机 0.0039)
D 标号逐字节相同 263/8192; A 的标号是 B 的仿射像: 0/64 轴
两实例对全部 16 字节都只给 1 个候选且一致 -> 合并增益 0 字节
```

跨实例复用**不会**多泄漏，因为单实例已经全取回；"对齐差"是随机的，两个实例的 `D` 相互独立。

## 十四、VM 层两条 P0 的落地与实测（2026-11-18）

§十三 的 P0 两条（“整块搬进一次调用”和“批量返回”）最后合成**一条**实现：
**一次调用算完整张 288 项偏移表，宿主从导出 VM 内存读回**。这一节记做法、数字和代价，全部来自
本机实跑（macOS arm64，`wbaes_vm2_clean`，密钥 `4f06…`）。

### 14.1 为什么是“一次算完 + 宿主缓存”，不是“九轮进字节码”

偏移只依赖调度块（族字节 + 布局字），与明文、密钥都无关，所以它是**每构建固定**的：
放进 VM 循环里每块重算一遍，得到的是同样 288 个数。把九轮数据面搬进字节码则是另一件事——
那要读 69 MB、要寄存器压力，而且省不下任何一次偏移计算。因此落地的形状是：

- 字节码自己走 `dir × round × i`（2 × 9 × 16），用 `St` 把 288 个偏移写进 VM 内存；
- 宿主算一次（`hy_vm_plan()`）后缓存 1152 B（`hy_vm_off[2][9][16]`）；
- 每块只比一次 64 B 调度块快照，变了就重跑一次 VM。

### 14.2 P0-b 的实现：导出 VM 内存，不加指令

`HSVMLowering.cpp` 降低时先找 `@hsvm_mem`（`[4096 x i8]`、非常量）：找到就把 4 KiB 全局当内存面，
每次调用照样先清零（语义与 alloca 版一致）；没有就退回原来的 alloca。`demos/wbaes/wbaes_vm.cpp`
定义这个数组，宿主在 `hsvm_entry` 返回后读它。**ISA 未改**：`HSVMOpcodes.def`、`sync_isa.py`、
解释器、oracle、`research/hsvm` 的 28 个 ctest、`scripts/verify_vmp_gate.sh` 全部原样通过
（它们不定义该全局，走 alloca 分支）。

### 14.3 实测

| 项 | 结果 |
|---|---|
| 字节码 | 61 条指令 / 488 B，6 条 `Tld`、1 条 `St`、5 `Brz`、4 `Jmp`（§5.26 那版是 43 / 344 B） |
| 降低后 `_hsvm_entry` | 206 条指令，间接 `br x*` **0** 条，`bzero` 目标 = `_hsvm_mem` |
| 一次调用算 288 项 | **0.86 µs**（微基准，5 次取最小） |
| 同样 288 项切成 18 次 (dir,round) 调用 | 15.2 µs（这就是原来每块在付的钱） |

`bge_attack.py` 与 `dca_attack.py` 在新产物上仍 0/16（rc=1）。

1. **VM 不再每块执行**。“热路径由字节码驱动”在这一代只对**表加载**成立；每块只剩一次 64 B
   快照比较。这是用 6 µs/块主动换的，写在这里而不是留给读者发现。
2. **偏移数值与改前逐位相同**，静态读表的人看到的地址序列不变。这一代买到的是耗时，不是新屏障。
3. **这一代仍被 residual 攻击打穿**：`attacks/residual/hs_attack.py` 在 `wbaes_vm2_clean` 上
   3.16 s 取回 `4f065a03…`（“reproduces the shipped ciphertext: YES”）。表结构与 dl5 相同，
   所以 §13.6 那条“把 hs_attack 写进闸门”的建议仍然成立：换钥不等于换结构。
   修复方向见 §13.6，本次没有改表结构。
4. 计划缓存（1152 B）在宿主内存里，dump 的对手能读到；那些值本来可由调度块 + 公开定位公式算出，
   不构成新增泄漏面。
5. §十三 的其余条目（P1 pass 侧状态复用、字节码优化、P2 随机化、P3 VM 内校验）本次都没做：
   P1 那两条在“每块一次调用都没有了”之后已经无关紧要，P2/P3 与本次目标无关。
