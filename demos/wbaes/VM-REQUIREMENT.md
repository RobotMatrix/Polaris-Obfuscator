# 硬要求：导出的白盒二进制必须包含 VM

## 结论先行

当前 `wbaes_dl3_*` **不含** VM（`strings | grep -c hsvm` = 0，节表只有 `__DATA,__hytab`）。
要满足"必须包含 VM"，产物必须由 `-passes=hsvm` 编译一份真实使用中的 HSV 字节码程序，
而不是附一个从不执行的字节码数组。

## 为什么不能"顺手加个 pass"

VM 内存 4 KiB、16 个寄存器；AES 一轮 16 次查表、每张表 64 KiB、全套 69 MB。
整轮搬进字节码需要 `Tld`（ISA v2 已实现并 gate 通过）把表访问引到宿主内存，
但 `Tld` 只是"能读"，还缺"把 9 轮写成 HSV 程序并接进 wbaes 生成流程"的生成器。
把整轮写成字节码属于后续方向（计算密集、寄存器压力大）。

## 本轮应采用的、可验证的落点

把**每轮的表偏移/调度计算**做成 HSV 字节码，并在加解密路径上真实调用：

```
输入: 调度块地址（宿主内存，含每轮的族编号与基址）
输出: 16 个字节的表偏移，写回宿主内存
实现: Tld 逐个读调度项 + 少量 Add/And/Shl，结果 St 回 4 KiB 内存
产物: 二进制里出现 @hsvm_bytecode 与 lowering 后的原生代码（无解释器残留）
```

这样 VM 进入热路径（每次加解密都要跑），而不是装饰；同时避开 69 MB 表必须进 VM 内存的矛盾。

## 判据

| 编号 | 判据 | 方式 |
|---|---|---|
| V1 | 产物里有 VM | `strings`/符号里能看到 lowering 后的入口；`otool`/`nm` 显示 `@hsvm_bytecode` 被消费，代码里无解释器分发循环 |
| V2 | VM 真被执行 | 破坏调度块一个字节 → 自检失败（证明 VM 输出被使用），恢复后 PASS |
| V3 | 函数不变 | 固定向量密文与未加 VM 时逐字节一致 |
| V4 | 性能 | 记录加解密耗时变化（VM 路径应为微秒级，不得出现数量级退化） |
| V5 | 双算不退化 | `-DWBAES_DFA_SELFTEST` 仍输出垃圾并 `vector-match FAIL` |
| V6 | 自检 | 生成端 `return 9` 与 demo 回环自检通过 |

## 顺序

dl4（内部编码）仍在跑且改同一批文件，VM 接线排在它之后，避免并发改动冲突：
1. dl4 落地并复核；
2. 写 HSV 字节码程序（调度/偏移计算）+ 生成器输出调度块 + demo 调用 `hsvm_entry`；
3. 跑 V1–V6，导出 `wbaes_vm_*`，README 写明"含 VM 的是这一代"。

## 2026-11-18 更新：口径改成“表加载时一次”，不是“每块都跑”

上面的落点（每次调用算 16 个偏移）已经在 `wbaes_vm.cpp` 里被替换：一次调用走
`dir × round × i`（2 × 9 × 16），用 `St` 把 288 个偏移写进 VM 内存，宿主从导出的
`@hsvm_mem` 读回并缓存（pass 侧只多了一条“有这个全局就用它、没有就退回 alloca”，
ISA 未改）。所以：

| 判据 | 现在的口径 | 实测 |
|---|---|---|
| V1 产物里有 VM | 不变 | `_hsvm_bytecode` `_hsvm_entry` `_hsvm_mem` `_hsvm_table` `_hsvm_table_len`；`_hsvm_entry` 间接跳转 0 |
| V2 VM 真被执行 | 每块不再调用；改调度块一个字节 → 快照不等 → 重走一次 VM → 偏移变 → 密文变 | 翻第 48 字节：`7672415a…` → `00ec5944…` → 恢复 `7672415a…` |
| V3 函数不变 | 不变 | 混合 + 四族强制，五次 `7672415a6313c58518fc95c9cb6922b8` |
| V4 性能 | 每块 288 次调用 → 0 次（整表一次 0.86 µs） | 23.34 / 23.15 → 16.93 / 16.85 µs（关 VM 下界 17.23 / 16.68） |
| V5 双算不退化 | 不变 | `-DWBAES_DFA_SELFTEST` 输出垃圾且 `vector-match: FAIL` |
| V6 自检 | 不变 | 生成端 rc=0、demo `roundtrip: PASS`、`tests/test_vm_offsets` PASS（含 288 项批量计划） |

“VM 进入热路径”这句话现在只对**表加载**成立：每块剩下的是一次 64 B 调度块快照比较。
这是明确用 ≈6 µs/块换的，理由（偏移与明文无关、每构建固定）写在 `WB-DESIGN-V2.md` §14.1。
