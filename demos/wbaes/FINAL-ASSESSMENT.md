# AES 兼容白盒：五代的实测结论与上限

## 一、实测总表

| 代 | 构造 | 表体积 | 每块耗时 | 静态出钥 | 轨迹出钥 | 备注 |
|---|---|---|---|---|---|---|
| dl | 数据层掩码（种子在二进制） | 69.2 MB | ~4.2 µs | 4.9 s | — | 种子=FNV(钥)，白送验钥 |
| dl2 | 随机种子 4 字分片 | 69.2 MB | ~4.2 µs | 5.0 s | — | 只多几分钟 |
| dl3 | 异构轮 F0–F3 + 调度块 | 69.8 MB | ~4.2 µs | 27.7 s | — | 实为降级（缺 Q 网络双射） |
| dl4 | lane 随机双射 + 32 位重编码 | 69.8 MB | ~4.5 µs | 17 s（bge 0.18 s 代数） | 0.68 s（8 条） | 秩-1 XOR 张量可分解 |
| dl5(nl) | 跨 lane 非线性重编码 | 70.09 MB | 22.3 µs | **18.5 s**（hs） | **~1 s（64 条）** | 正则 (Z2)^8 + 规范不变检验 |
| vm2 | 上代 + VM 一次算 288 偏移 | 70.09 MB | 16.9 µs | 18.5 s | ~1 s | 性能改动，天花板未动 |
| Z 路 | rk0 移入输出双射 | 70.11 MB | 8.8 µs | **0.00 s** | — | 修正层被迫含 S∘σ_k ⇒ 256 项指纹 |
| 融合 | 2^16 pair 表 + 合并表 | 69.80 MB | 16.6 µs | 1.4 s | — | 合并和只有 8 位宽 |
| **W16 (出货)** | **16 位部分和（AES 兼容）** | **70.09 MB** | **13.4 µs（-20%）** | **0.08 s 代数 / 4,096 检验** | 未测 | 编码被迫仿射 ⇒ 精确 XOR 可分 |

W16 自 2026-11-18 起是**出货形状**（`wbaes_f4_clean` / `wbaes_f4_max`，`HY_FAM_W16` 是代码里
唯一的形状）。出去的理由不是强度，而是它的三种性质：密文等于 AES、快 20 %、体积不变；
取钥强度明确更低（4,096 次检验）。见 `README.md` §5.29 与 `WB-DESIGN-V2.md` §16.1。

## 二、上限（本项目五代的实测支持）

**在"表可读 + 合并发生在字节层"的 AES 兼容构造里，密钥提取恒在 2^8 检验/字节量级。**

- 8 位合并（dl4/dl5/融合）⇒ 存在 256×256 的 8 位值表，行是置换 ⇒ Decomp 可分解；
- 16 位合并（W16）⇒ 可携带的编码被迫是仿射的（否则 E0=E1 且 E(u⊕v)=E(u)⊕E(v) 不成立，
  实测 4096 对里 119 个反例）⇒ 2^16 表精确 XOR 可分，一轴仍给一字节；
- 所以"加宽"买到的是**性能**（-20%）而不是强度，反而把检验数从 16,384 降到 4,096。

## 三、不能靠"隐藏"补的部分

- 算法身份：块长 16、9 轮、MixColumns 代数指纹（`FINGERPRINT.md`）；
- 表结构与代数：Q=Z(D0⊕D1) 可分解 2,097,152/2,097,152；
- 导出硬化（符号/节名/已知答案/表形态）得分 155→0，但出钥时间 23.8 s → 20.0 s（`reports/EXPORT-HARDENING.md`）。

## 四、买到的与买不到的

```
买到（可对外讲）
  DFA 双算：单故障被拦，输出随机垃圾（V5 每次实测）
  封印 + 负向测试：改坏调度块/表项必自检失败
  VM：轮控制流 lowering 后无分发循环，且每块 0 开销（288 → 1 次调用）
  导出硬化：提示信息 155→0，首小时判别成本上升
  CFF/BCF：体积 +2.9~13.5%、块 +8.6~43.8%，对密钥提取 0
  随机化：对旧脚本无效化，但对会数命中次数的对手只有 1.04–1.16×（+11~41% 时延）

买不到（必须写进结论）
  任何表结构级密钥保护：2^8 检验/字节，五代未动，W16 更低（2^8 但总数更少）
  抗轨迹攻击：64 条轨迹 ~1 s；随机化只买常数
  算法可识别性：几分钟内可确认为 AES-128
```

## 五、下一步只有两条（不再在 8 位/16 位切片上变形）

1. **换密码**（不要求 AES 兼容）：16 位 S 盒的 WB 设计（SPNbox/WhiteBlock/SPACE 类），
   合并宽度天然 ≥16 位且 S 盒非 AES 结构；需重测五条攻击的工作因子，判据仍是"每字节 ≥2^16 且无捷径"。
2. **接受并转移**：表层隐藏状态不隐藏密钥；把强度记在 DFA + 封印 + VM + 硬化上，
   密钥保护交给"秘密不在产物内"（口令/设备密钥/TEE）——这条与行业现状一致（`WB-DESIGN-V2.md` §九）。

## 六、闸门写法（本项目教训）

```
错误写法：这些脚本失败 ⇒ 已加固
正确写法：每密钥字节的检验次数 ≥ 2^k，且给出可复算的攻击脚本与耗时
理由：融合代五个脚本全失败、密钥仍被 1.4 s 拿到；W16 四代脚本失效、费用 0.08 s
```

## 七、导出策略（2026-11 定）

**只导出强度最高的那一代，且在所有功能完成之后一次性导出。** 依据是"每密钥字节的检验次数"，不是速度、不是体积：

```
对外唯一产物   wbaes_vm2_max（nl 结构 + VM 装载期一次算 288 偏移）
              16,384 次检验 / 18.5 s 静态出钥 / 64 条轨迹 ~1 s
内部保留       macos/ 下其余九代，仅用于回归与对照（verify_all.py 覆盖）
不进对外包     f4（4,096 次检验，更快但更弱）、融合（同 16,384 但少四族维度）、
              Z 路（0.00 s 指纹，只作为反面结论）
```

理由：`f4` 的 16 位合并被迫仿射，表精确 XOR 可分，出钥成本 0.08 s——按强度排序它比 nl 弱一个量级，
即使快 20%。若将来需要"AES 兼容 + 性能"的例外，必须显式记录强度下降，不能默认发布。

**导出时机：暂缓。** 目前仍在推进 MIR 拆分强化（S1 已落地，A/B 档收口与 S2/S4 未完成），
在这些功能定型前不产出对外包——避免"发出去又换一版"以及旧包与新结论不一致。
最终导出前必须逐项确认：

```
