# 用仿射隐藏"多轮"结构：设计与实施计划

## 一、当前结构暴露了什么

`wbaes_hybrid.inc:68` 的运行时形状就是明文的轮数：

```c
for (int r = 0; r < HY_MC_ROUNDS; r++)
    hy_mc_round(HYKTAB, hy_enc_col(r, 0), r, 0, 1, s, n, env);
```

逆向者不需要理解表，只要数循环次数、看 `hy_enc_col(r, …)` 的步长，就知道是 9 轮 + 末轮。
表区布局也按 `(dir, round, col, side)` 分块（`hy_tag`），轮边界是**物理可见**的。

## 二、仿射能做与不能做的事（先把边界说清）

**能做的：轮间字节级仿射重编码（relabeling）。**
对每个轮边界 r 取一个仿射双射 `A_r(x) = a_r·x ⊕ b_r`（GF(2^8)，`a_r ≠ 0`），要求：

- 第 r 轮的输出侧表存 `A_r(v)`；
- 第 r+1 轮的输入侧表以 `A_r(v)` 为索引，即用 `S(A_r^{-1}(b) ⊕ k_{r+1})` 建表。

运行时**不需要任何新指令**：只是把第 r+1 轮表的行按 `A_r` 置换、把第 r 轮表的值按 `A_r` 编码。
收益：每轮看到的字节值都落在不同的仿射坐标系里，`表项 = S(pt ⊕ k)` 这条直线关系在轮内不再成立。

**不能做的：把轮数从代码里抹掉。**
`A_r` 是逐字节的，而轮间还有 `MixColumns`（4 字节线性混合）。若把 `A_r` 插在 MixColumns **之后**、
下一轮 SubBytes **之前**，则必须改写下一轮的 S 盒为 `S∘A_r^{-1}` —— 这只是"换了一张 S 盒"，
轮边界依然存在，循环依然是 9 次。要真正抹掉轮边界，需要 Chow 式的宽表融合
（把 MixColumns 折进 32 位宽表，轮与轮之间只剩 XOR），那是另一种数据规模（表从 64 KiB/张变成 4 GiB/张，
或用 GF(2^8) 上的 MDS 分解成 4 张 8-bit 表 + XOR 网络）。

## 三、实施步骤（每步都有可执行判据）

1. **生成端**：`gen_hybrid.cpp` 增加 `A[HY_MC_ROUNDS][16]`（每轮每字节一个 `a,b`），
   在 `fill_xor_round` 的**输入侧**用 `A_{r-1}^{-1}` 反查、**输出侧**存 `A_r(v)`；
   第 0 轮保留现有 `P0`（它已经是一个特例，`A_{-1} = P0`）。
2. **自检**：生成器内既有的回环自检（`demo_wbaes.cpp:1085-1090` 与生成端 `return 9` 分支）必须仍然通过，
   密文必须与改动前**逐字节一致**（仿射只是换坐标，不改变函数）。
3. **运行时**：`wbaes_hybrid.inc` 不改一行（这是"纯 relabeling"的判据）。
4. **反向验证**：`extract_key.py` 在改动后仍应能出钥（它按 64K 表一致性搜索，不依赖坐标）——
   如果能出钥，说明改动没有破坏自己的一致性；如果出不了，说明我建表写错了，必须先修表再谈安全。
5. **文档**：`DATA-LAYER.md` 增一节，写明"每轮不同仿射坐标，但轮边界仍可见、提取成本不变"。

## 四、为什么单独立项而不是顺手改

上一轮把 `P0i` 加到解密尾部就触发过 `return 9`（回环自检失败），原因是**内部语义与外部编码混在一起**。
轮间仿射比 P0 更危险：它同时碰 10 个轮边界、加密与解密两条路径、以及 DFA 双算的两份缓冲。
按仓库铁律，改动必须整块落地并跑通自检，不允许"先加一半、等下次"。

## 五、宽表融合的第一步：32 位 T-box 参考模型（已实测）

`demos/wbaes/fused_round_ref.cpp` 把一轮 AES 折成"四次 32 位查表 + XOR"：

```
T[p][x] = MC(·, row) · S(x)          p = 4*col + row，输出 32 位
out_col = T[p0][in[p0]] ^ T[p1][in[p1]] ^ T[p2][in[p2]] ^ T[p3][in[p3]] ^ rk_col
```

关键性质：**表路径里没有 SubBytes、没有 ShiftRows、没有 MixColumns 矩阵**——
线性层被烘进表的 32 位输出，索引置换就是 ShiftRows。

实测（2000 组随机输入/轮密钥，与明文轮逐字节比对）：
```
PASS: fused 32-bit T-box round == SubBytes+ShiftRows+MixColumns+AddRoundKey on 2000 vectors
```

这是融合的判据基线：先证明"折进表里"是对的，再谈把它接进 `gen_hybrid` 的生成流程
（接的时候还要成对处理：输出侧随机仿射 + 下一轮输入侧取逆，以及加密/解密两条路径）。

## 六、每轮不同实现（异构轮），已实测

同一轮函数可以有多种实现形状，按轮调度，代码里九轮不再同构：

| 家族 | 形状 | 轮内可见操作 |
|---|---|---|
| F0 plain | S 盒 + ShiftRows + MC 矩阵 + 轮密钥 XOR | 经典四步 |
| F1 t32 | 4 次 32 位查表 XOR，线性层烘进表 | 无 MC、无 SR 指令 |
| F2 t8 | 16 张带 MC 系数的字节表，逐字节 XOR 累加 | 无 MC 矩阵 |
| F3 keyed | 同 F1，但列密钥并入某张表的 32 位输出 | **连密钥 XOR 都没有** |

实测：2000 组随机 (state, round_key) 上四族逐字节一致
```
PASS: 4 round families agree on 2000 vectors (plain / t32 / t8 / keyed)
```

**踩到的坑（值得记住）**：F3 最初把轮密钥并进表的**索引**（`S(x ^ k)`），三族全错。
原因是 SubBytes 非线性——常数在 S 之前 XOR 进去不会以常数的形式出来。
正确做法是并进表的**输出**：每列指定一个源，把整列密钥字 XOR 到那张表的 32 位值上，
运行时就没有密钥 XOR 这一步了。这也说明"仿射/线性技巧"在 S 盒两侧不能随意搬。
